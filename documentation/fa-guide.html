راهنمای فارسی AStack Enterprise

سیستم‌عامل هوش مصنوعی برای هر نوع کار: نرم‌افزار، پرونده حقوقی، مالی، مالیاتی، حسابداری، بازاریابی، عملیات، منابع انسانی، تحقیق و کسب‌وکار.

۱۰ دامنه کاری ۳۳ دپارتمان ۲۱۹ نقش تخصصی ۲۷ ورک‌فلو رانتایم اصلی: Claude Code

AStack چیست؟

AStack یک سیستم‌عامل ماژولار برای کارِ اداره‌شده با هوش مصنوعی است. شما هدف را به زبان خودتان می‌گویید؛ سیستم دامنه کار را تشخیص می‌دهد، تیم متخصص می‌سازد، برای هر نقش یک ایجنت ایجاد می‌کند، کارها را به صورت مأموریت‌های زمان‌بندی‌شده تفویض می‌کند و پیشرفت را با معیارهای واقعی مدیریت پروژه (اسپرینت، ریسک، پیش‌بینی، سلامت) گزارش می‌دهد.

  • ارتباط با شما: فارسی. کد و داده‌ها: انگلیسی.
  • همه‌چیز محلی است: هیچ سرور یا API شبکه‌ای وجود ندارد؛ وضعیت در فایل‌های .astack/ و حافظه در memory/ نگهداری می‌شود.
  • قانون هماهنگی: دپارتمان‌ها و ایجنت‌ها هرگز مستقیم با هم صحبت نمی‌کنند؛ ارکستریتور و لایه رهبری همه‌چیز را هماهنگ می‌کنند.

شروع سریع

npm test
node bin/astack.mjs doctor
node bin/astack.mjs domain detect "اظهارنامه مالیات ارزش افزوده"
node bin/astack.mjs lead plan "پرونده حقوقی قرارداد ملکی"
node bin/astack.mjs lead team "پرونده حقوقی قرارداد ملکی" --name legal-case-team
node bin/astack.mjs project init "Contract Dispute" --template legal-case
node bin/astack.mjs lead delegate contract-dispute --team legal-case-team
node bin/astack.mjs agent run-due
node bin/astack.mjs lead standup

پیش‌نیازها فقط Node.js نسخه ۲۰ به بالا و git است؛ هیچ وابستگی npm نصب نمی‌شود.

چرخه رهبری

لایه رهبری همان چیزی است که AStack را از یک مشاور به یک مدیر تبدیل می‌کند. چرخه استاندارد:

  1. lead plan — تشخیص دامنه و پیشنهاد ورک‌فلو و ترکیب تیم.
  2. lead team — تشکیل تیم و ساخت یک ایجنت برای هر نقش.
  3. project init --template ... — تبدیل هدف به پروژه مرحله‌بندی‌شده.
  4. lead delegate — تبدیل آیتم‌های آماده پروژه به مأموریت ایجنت‌ها (توزیع چرخشی بین هم‌تخصص‌ها؛ آیتم‌های must با اولویت بالا).
  5. agent run-due — صدور «دستور کار» برای مأموریت‌های سررسیدشده در outbox هر ایجنت.
  6. اجرای هر دستور کار توسط رانتایم (Claude Code در نقش همان ایجنت) و ثبت نتیجه با agent report.
  7. lead standup و lead review — نظارت، پیگیری سررسیدها و بازبینی خروجی‌ها قبل از ارائه به شما.

تیم‌ها

تیم‌ها از نقشه دامنه ساخته می‌شوند (یک سرپرست + اعضای متخصص) و در .astack/teams/ نگهداری می‌شوند. وضعیت‌ها: forming، active، paused، disbanded.

node bin/astack.mjs team create "Legal Case Team" --domain legal --mission "..."
node bin/astack.mjs team list
node bin/astack.mjs team show legal-case-team
node bin/astack.mjs team add legal-case-team --role vat-specialist --dept tax
node bin/astack.mjs team project legal-case-team contract-dispute
node bin/astack.mjs team disband legal-case-team

نام تیم‌ها (و پروژه‌ها و ایجنت‌ها) باید حروف لاتین داشته باشد چون شناسه ذخیره‌سازی می‌شود؛ مأموریت و توضیحات می‌تواند کاملاً فارسی باشد.

ایجنت‌ها و زمان‌بندی

هر ایجنت یک همکار پایدار است: نقش، دپارتمان، تیم، مأموریت و فهرست مأموریت‌های زمان‌بندی‌شده دارد. وضعیت ایجنت: idle → active → paused → retired.

زمان‌بندی مأموریت

  • تکرارشونده: --every 30m | 1h | 4h | 1d | 1w — بعد از هر گزارش، اجرای بعدی خودکار تنظیم می‌شود.
  • یک‌باره: بدون --every (فوری) یا با --at برای زمان مشخص.
node bin/astack.mjs agent create "case researcher" --role legal-researcher --team legal-case-team
node bin/astack.mjs agent assign case-researcher "خلاصه پرونده‌های جدید" --every 1d --deliverable "گزارش روزانه"
node bin/astack.mjs agent run-due
node bin/astack.mjs agent report case-researcher A-1 --summary "گزارش آماده شد"
node bin/astack.mjs agent standup
node bin/astack.mjs agent pause case-researcher

دستور کار (Work Order)

هر اجرا یک فایل Markdown در .astack/agents/<agent>/outbox/ می‌سازد: نقش، تیم، اولویت، مأموریت، هدف، خروجی مورد انتظار و روش گزارش‌دهی. رانتایم این فایل را در نقش همان ایجنت اجرا می‌کند و نتیجه با agent report ثبت می‌شود. هر صدور و گزارش در حافظه agent نیز ثبت می‌شود تا رد کامل کارها باقی بماند.

مدیریت و تحویل پروژه

موتور تحویل هر کار جدی را به یک پروژه مرحله‌بندی‌شده تبدیل می‌کند: initiation → planning → execution → closing → closed با دروازه‌هایی که بدون احراز شرایط اجازه عبور نمی‌دهند.

  • تخمین سه‌نقطه‌ای PERT و مسیر بحرانی با احتمال تحویل به‌موقع
  • بک‌لاگ رتبه‌بندی‌شده با MoSCoW و WSJF، بورد کانبان با محدودیت WIP
  • اسپرینت با ظرفیت مبتنی بر سرعت واقعی، دفتر ریسک امتیازدهی‌شده
  • پیش‌بینی مونت‌کارلو (p50/p85/p95)، مدیریت ارزش کسب‌شده (EVM)، امتیاز سلامت شفاف
  • پیشنهاد «اقدام بعدی» و گزارش وضعیت فارسی با project status و project report

ارتقای هسته

هر پروژه‌ای که AStack درون آن است با یک فرمان به آخرین نسخه می‌رسد:

node bin/astack.mjs upgrade --check   # پیش‌نمایش بدون تغییر
node bin/astack.mjs upgrade           # دریافت، پشتیبان‌گیری، اعمال
node bin/astack.mjs doctor            # تأیید سلامت بعد از ارتقا
  • فایل‌های موتورها جایگزین می‌شوند؛ از هر فایلِ تغییرکرده اول نسخه پشتیبان در .astack/backups/upgrade-*/ گرفته می‌شود.
  • astack.config.yaml و CLAUDE.md شما بازنویسی نمی‌شوند؛ فقط سکشن‌های جدید کانفیگ به انتها اضافه می‌شوند.
  • .astack/، memory/، پلاگین‌ها و knowledge packها هرگز لمس نمی‌شوند. مسیرهای سفارشی را در upgrade.keep ثبت کنید.

پروژه‌های خیلی قدیمی

اگر نسخه قدیمی موتور ارتقا را ندارد، فقط فایل scripts/astack-upgrade.mjs را داخل پروژه کپی کنید و اجرا کنید: node astack-upgrade.mjs. این اسکریپت آخرین هسته را دریافت می‌کند و منطق ارتقای «جدید» را اجرا می‌کند؛ بنابراین همه امکانات نسخه ۲ (دامنه‌ها، تیم‌ها، ایجنت‌ها، رهبری) یک‌جا وارد پروژه قدیمی می‌شود. جزئیات: Upgrade.md

حافظه و زبان‌ها

حافظه: یازده اسکوپ پایدار در memory/ شامل اسکوپ‌های جدید team و agent. اسکوپ decision خوراک کالیبراسیون است: با بستن هر پروژه، نسبت تخمین به واقعیت ثبت می‌شود و تخمین‌های بعدی دقیق‌تر می‌شوند. با astack backup از همه اسکوپ‌ها نسخه پشتیبان بگیرید.

زبان‌ها: رابط کاربری چهار زبان دارد — فارسی (پیش‌فرض)، انگلیسی، عربی و ترکی — با فالبک خودکار به انگلیسی. تشخیص دامنه و ورک‌فلو از پایه دوزبانه (فارسی/انگلیسی) است. صفحه اول مخزن نیز به چهار زبان موجود است: README.md · README.fa.md · README.ar.md · README.tr.md
