راهنمای فارسی AStack Enterprise

AStack Enterprise؛ سیستم‌عامل مهندسی نرم‌افزار مبتنی بر AI

این سند راهنمای فارسی کامل پروژه است. هدف آن این است که مالک پروژه، Claude Code و هر agent آینده بتوانند ساختار، دستورها، قراردادها، مسیر توسعه و استانداردهای عملیاتی AStack Enterprise را سریع و دقیق بفهمند.

اصول محصول

AStack Enterprise یک prompt collection یا skill repository ساده نیست. این پروژه به‌عنوان یک پلتفرم بلندمدت برای مدیریت کار مهندسی، معماری، بازبینی، توسعه، مستندسازی، memory و orchestration ساخته شده است.

محور اصلی اجرای عملی داخل Claude Code و آماده بودن برای توسعه‌ی چندساله.
اصل معماری هر subsystem باید decoupled، قابل‌تست، قابل‌جایگزینی و قابل‌گسترش باشد.
زبان ارتباط با مالک تمام پیام‌ها، گزارش‌ها، سوال‌ها، هشدارها و تحلیل‌ها فارسی هستند.
زبان دارایی‌های نرم‌افزاری کد، command، identifier، API route، database name، commit message و documentation پیش‌فرض انگلیسی می‌مانند.

شروع سریع

بعد از clone کردن repo، از ریشه‌ی پروژه این دستورها را اجرا کنید:

npm test
node bin/astack.mjs doctor
node bin/astack.mjs review "Laravel security deployment"
اگر خروجی AStack Enterprise verification passed. و پیام سلامت فارسی را دیدید، runtime اصلی آماده است.

اجرای داخل Claude Code

فایل اصلی راه‌اندازی Claude Code در ریشه‌ی پروژه قرار دارد: CLAUDE.md

ترتیب پیشنهادی load شدن context در Claude Code:

  1. CLAUDE.md برای قوانین عملیاتی پروژه.
  2. astack.config.yaml برای configuration مرکزی.
  3. system/language-policy.md برای سیاست زبان فارسی/انگلیسی.
  4. runtime/astack-runtime.mjs برای نقشه‌ی runtime.
  5. orchestrator/orchestrator.mjs برای routing درخواست‌ها.
  6. departments/departments.json و roles/enterprise-roles.json برای انتخاب تیم و نقش‌ها.
  7. workflow-engine/workflows.json برای انتخاب workflow.
  8. memory-engine/memory-engine.mjs برای حافظه‌ی پایدار.
قانون مهم: Departmentها مستقیم با هم صحبت نمی‌کنند. هماهنگی فقط از طریق Orchestrator انجام می‌شود.

معماری Enterprise

ساختار پروژه layered است و هر لایه مسئولیت مشخص دارد. این طراحی باعث می‌شود اضافه کردن provider، plugin، department، workflow یا knowledge pack بدون تغییر core انجام شود.

لایه مسیر مسئولیت
Corecore/قراردادهای پایه و manifest اصلی پلتفرم.
Runtimeruntime/composition root و اتصال subsystemها.
Orchestratororchestrator/تحلیل intent، انتخاب workflow، فعال‌سازی departmentها و merge خروجی‌ها.
Departmentsdepartments/تعریف تیم‌های تخصصی مثل Engineering، DevOps، SEO و Security.
Rolesroles/catalog نقش‌های تخصصی Enterprise.
Providersproviders/manifestهای provider مثل claude-code، openai و ollama.
Knowledge Packsknowledge-packs/بسته‌های تخصصی مستقل مثل Laravel، Docker، RAG و SEO.
Pluginsplugins/افزونه‌های جداگانه که بدون تغییر core اضافه می‌شوند.
Memory Enginememory-engine/مدیریت memory scopeهای پایدار.
Workflow Engineworkflow-engine/تعریف و انتخاب workflowهای Enterprise.
Localization Enginelocalization-engine/مدیریت locale، fallback و ترجمه‌ی پیام‌های CLI.
Configuration Engineconfiguration-engine/خواندن و اعتبارسنجی configuration مرکزی.
Event Busevent-bus/ثبت eventهای داخلی و اتصال loosely coupled subsystemها.
Permission Systempermission-system/سیاست least privilege و محافظت از secrets.

CLI اصلی در bin/astack.mjs قرار دارد. خروجی کاربرمحور آن فارسی است، اما خود commandها انگلیسی می‌مانند.

Orchestrator

Orchestrator مغز هماهنگی AStack Enterprise است. وظیفه‌ی آن این است که درخواست مالک را بفهمد، workflow مناسب را انتخاب کند، departmentهای مرتبط را فعال کند، provider مناسب را انتخاب کند و خروجی نهایی را به شکل فارسی و قابل‌اقدام برگرداند.

مسیر فعلی اجرا

  1. دریافت request از CLI یا agent runtime.
  2. تحلیل intent با توجه به متن درخواست.
  3. انتخاب workflow از workflow-engine/workflows.json.
  4. انتخاب departmentها از departments/departments.json.
  5. انتخاب provider پیش‌فرض، در حال حاضر claude-code.
  6. ساخت پاسخ نهایی فارسی و ثبت event در Event Bus.

Departmentها و Roleها

پروژه شامل ۲۷ department و ۱۹۰ role تخصصی است. این roleها در roles/enterprise-roles.json ثبت شده‌اند و برای توسعه‌ی تخصصی Enterprise استفاده می‌شوند.

Engineering AI Engineering Backend Frontend Mobile DevOps Infrastructure Cyber Security Database SEO Marketing QA

نمونه roleها: Principal Laravel Engineer، Principal TypeScript Engineer، RAG Specialist، Kubernetes Specialist، VMware ESXi Specialist و Technical SEO Specialist.

Providerها

Providerها abstract هستند و از مسیر providers/ بارگذاری می‌شوند. اضافه کردن provider جدید باید فقط با ساخت یک directory و manifest.json انجام شود و نیازی به تغییر core نداشته باشد.

claude-code openai codex gemini openrouter ollama local-models deepseek

Knowledge Packها

Knowledge Packها بسته‌های تخصصی مستقل هستند. هر pack شامل best practices، coding standards، architecture rules، review rules، templates، examples، checklists، common mistakes و latest recommendations است.

Memory Engine

Memory Engine برای نگهداری context پایدار استفاده می‌شود. Scopeهای فعلی در مسیر memory/ قرار دارند.

  • global: حافظه‌ی عمومی AStack.
  • project: تصمیم‌ها و اطلاعات همین پروژه.
  • department: حافظه‌ی مرتبط با departmentها.
  • role: حافظه‌ی roleهای تخصصی.
  • decision: تصمیم‌های معماری و محصول.
  • coding-standards: استانداردهای کدنویسی.
  • architecture: حافظه‌ی معماری.
  • business: قوانین و جهت کسب‌وکار.
  • user-preferences: ترجیحات مالک پروژه.
node bin/astack.mjs memory
node bin/astack.mjs backup

Workflow Engine

Workflowها در workflow-engine/workflows.json تعریف شده‌اند. Orchestrator با توجه به intent درخواست، workflow مناسب را انتخاب می‌کند.

idea discovery architecture planning implementation review qa security deployment seo marketing release maintenance bug-fix refactor feature mvp startup-validation documentation

Plugin System

مسیر plugins/ برای extension pointهاست. هر plugin باید فایل plugin.json داشته باشد و خودش را به‌صورت مستقل معرفی کند.

نمونه‌ی ساختار plugin:

plugins/my-plugin/
  plugin.json
  plugin.mjs
  README.md

اصل طراحی این است که اضافه کردن language، framework، department، provider، workflow یا role جدید بدون تغییر core انجام شود.

Localization

مالک AStack فارسی‌زبان است؛ بنابراین تمام ارتباطات کاربرمحور فارسی هستند. در عین حال دارایی‌های نرم‌افزاری برای production و همکاری بین‌المللی انگلیسی باقی می‌مانند.

فارسی انگلیسی
سوال‌ها، هشدارها، گزارش‌ها، تحلیل‌ها، توضیح معماری، progress و errorهاکد، command، function، class، variable، API route، database table، migration، Dockerfile، YAML key و JSON key

سرویس localization در localization-engine/service.mjs قرار دارد و localeهای فعلی شامل fa، en، ar و tr هستند.

GitHub و Release

پروژه برای push شدن به private GitHub repository آماده شده است. مسیر .github/ شامل workflowها، issue templateها، PR template، labels و CODEOWNERS است.

  • .github/workflows/verify.yml: اجرای تست‌ها روی push و pull request.
  • .github/workflows/release.yml: بررسی release هنگام tag semantic version.
  • .github/pull_request_template.md: قالب pull request.
  • .github/ISSUE_TEMPLATE/: قالب‌های issue.
  • .github/CODEOWNERS: مالکیت فایل‌ها.

تست و سلامت سیستم

تست اصلی در tests/verify-astack.mjs قرار دارد و وجود لایه‌های Enterprise، Claude Code readiness، providerها، role catalog، knowledge packها، workflowها، memory scopeها و policyهای امنیتی را بررسی می‌کند. 

npm test
node bin/astack.mjs doctor --claude-code
خروجی موفق باید شامل AStack Enterprise verification passed. و گزارش سلامت فارسی باشد.

چک‌لیست commit نهایی

  1. اجرای تست کامل: npm test
  2. اجرای doctor: node bin/astack.mjs doctor --claude-code
  3. بررسی فایل‌های تغییرکرده: git status --short
  4. ساخت اولین commit با پیام انگلیسی، مثل: feat: initialize AStack Enterprise platform
  5. ساخت private repository در GitHub.
  6. اتصال remote و push کردن branch اصلی.
git add .
git commit -m "feat: initialize AStack Enterprise platform"
git remote add origin git@github.com:YOUR_USERNAME/YOUR_PRIVATE_REPO.git
git push -u origin main
قبل از push مطمئن شوید هیچ secret، token یا API key داخل repo قرار نگرفته است.
