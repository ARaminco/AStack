# Plan review checklist

- [ ] Plan and the code it touches read; earlier decisions recalled from memory.
- [ ] Real problem, target outcome and cost of doing nothing named.
- [ ] Existing code and packages mapped to each sub-problem.
- [ ] Mode recommended with a concrete reason; the owner chose it.
- [ ] Each addition or cut asked separately; nothing changed scope silently.
- [ ] Deferred items recorded with reasons; rejected items under NOT in scope.
- [ ] Complexity gate applied (8+ files or 2+ new services).
- [ ] Architecture, data flow diagram, edge cases and error/rescue map written.
- [ ] Test matrix covers every new branch, including denied and negative cases.
- [ ] Performance findings carry a scale or "unknown".
- [ ] Rollout, migration order and rollback described.
- [ ] Design scored on seven dimensions when the plan has UI.
- [ ] Owner challenges never auto-decided; taste decisions listed at the gate.
- [ ] Review saved and read back; brief presented in Persian; decisions recorded.
